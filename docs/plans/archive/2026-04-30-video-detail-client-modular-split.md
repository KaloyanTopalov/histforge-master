# Modular split of video-detail-client.tsx

## Overview
Continue the modular split that's already underway in `src/app/videos/[id]/` (`_shared`, `video-actions.tsx`, `flow-accounts-strip.tsx`) by extracting three self-contained subsystems out of `video-detail-client.tsx` into sibling components: the moderation panel, the Flow progress card, and the artifacts card. The orchestrator keeps the props contract, polling effects, top-level state, and overall page layout — only rendering trees move. Closes audit finding #3 from `docs/refactoring/solid-audit-2026-04-30.md`.

## Current State

**File under refactor**
- `src/app/videos/[id]/video-detail-client.tsx` — 646 lines as of HEAD (was 730 at audit time; finding #1 / #2 already trimmed the artifact-grouping logic into `lib/`). The orchestrator now mixes six concerns: top-level video state + polling (lines 264-345), Flow-side polling and the `requeueFailed` action (347-399), the Steps card (454-494), the Flow progress card with `FlowCountsRow` / `sumCounts` (210-252, 496-575), the moderation panel and row (110-204), and the artifacts card (583-643). Three of these — the Flow progress card, the moderation panel, and the artifacts card — are the SRP-violating tenants this plan evicts; the other three (video state + polling, Flow-side polling, Steps card) are page-level and stay.

**Pattern to mirror — siblings already in this directory**
- `src/app/videos/[id]/flow-accounts-strip.tsx:1-58` — `"use client"` sibling that takes a typed props object, owns its own rendering tree, and is consumed by the orchestrator with one line. This is the target shape for each extraction.
- `src/app/videos/[id]/video-actions.tsx:1-248` — sibling that owns its own internal state (`inflight`, `confirmDelete`, `confirmRestart`, `error`, `copied`) and only surfaces props it actually needs from the parent. Confirms that local UI state belongs in the panel, not the orchestrator (the moderation panel's `expanded` toggle and the Flow progress card's `showFailed` toggle are both candidates).
- `src/app/videos/_shared.tsx:19-126` — module of small presentational helpers (`StatusBadge`, `SectionHeading`, `DeletingLabel`, …) consumed across the videos surface. The duration helpers (`formatDuration`, `stepDuration`, `totalDuration`) and `STEP_ICONS` / `STEP_ICON_COLORS` are exclusive to the Steps card and should stay inline — the audit explicitly notes pure helpers "are not the concern."

**Pieces that stay in the orchestrator** (per audit: "polling, top-level state, and overall layout")
- All state hooks: `video`, `steps`, `artifacts`, `workflowLabel`, `queueState`, `flowSummary`, `flowAccounts`, `requeuing`, `now`, plus the `tickRef`.
- The video poll effect (306-345), the per-second clock (290-304), and the Flow poll effect (368-377). `refreshFlowSummary` / `refreshFlowAccounts` (347-366) and `requeueFailed` (379-399) stay too — `requeueFailed` mutates orchestrator state (`setRequeuing`) and triggers `router.refresh()`, both of which are page-level concerns.
- The header layout (409-446), the failed-reason `<pre>` (448-452), the Steps card (454-494), and the prop-typed export.

**Tests in scope**
- `__tests__/components/videos/video-detail-client.test.tsx` (729 lines, 15 tests) — RTL coverage that renders `<VideoDetailClient>` and asserts on the rendered output (status icons, polled step transitions, paused/deleting badge precedence, Flow progress panel gating, moderation events, artifact list updates). Baseline confirmed green (`npx vitest run __tests__/components/videos/video-detail-client.test.tsx` — 15/15 pass) before refactor begins. The file passes `initialLogExists={false}` to every render, which is stale — `VideoDetailClientProps` no longer declares it (the prior `logExists` plumbing-removal landed without updating the test). vitest's runtime tolerates the excess prop, but **`tsc --noEmit` already errors on every render call in this file pre-refactor** (≈10 `initialLogExists` excess-property errors plus several `'is not assignable to type Video'` fixture-shape errors on the `video()` helper). These are pre-existing tech debt; cleaning up the stale props and broken fixture is out of scope for this plan. Task 4's tsc step (below) is therefore "verify no _new_ errors in the four touched src files" — not a clean-tree gate.

**Convention to honor in new files**
- All sibling components in this directory annotate `): JSX.Element` (or `: JSX.Element` for arrow-form internals) — see `flow-accounts-strip.tsx:22`, `video-actions.tsx:47`, `_shared.tsx:19/30/95`. New extracted components follow suit.

## Scope

**Doing**
- Extract `flow-moderation-panel.tsx` — the `ModerationPanel` + `ModerationRow` rendering tree and its private helpers (`truncate`, `PROMPT_PREVIEW_CHARS`).
- Extract `flow-progress-panel.tsx` — the entire Flow progress `<Card>` layout, with `FlowCountsRow`, `sumCounts`, and the `showFailed` toggle moving inside.
- Extract `artifacts-panel.tsx` — the entire Artifacts `<Card>` and its `useMemo(groupArtifactsByStep)` call.
- Keep the orchestrator's props contract (`VideoDetailClientProps`) byte-identical so `page.tsx` is not touched.
- Keep the `export type { FlowSummary } from "@/lib/flow-summary";` re-export at line 37 — it's a public re-export through the orchestrator's module path and may have external consumers; preserve it even though the orchestrator's body no longer references the type after Task 2.

**Not doing**
- Extracting the Steps card. The audit doesn't request it, and the steps list is the page's primary content — keeping it inline preserves a clear "this is what this page is" cue at the top of `VideoDetailClient`.
- Hoisting Flow-side polling state out of the orchestrator into `flow-progress-panel.tsx`. The audit explicitly keeps polling in the orchestrator. The panel takes `flowSummary`, `flowAccounts`, `requeuing`, and `onRequeueFailed` as props.
- Lifting the duration / step-icon helpers (`formatDuration`, `stepDuration`, `totalDuration`, `stepNumber`, `STEP_ICONS`, `STEP_ICON_COLORS`) into `_shared.tsx`. They're only used by the Steps card that stays in this file — moving them just for tidiness adds a hop without reducing concern-mixing.
- Audit finding #4 (`humanizeStepName` provider regex) — separately tracked, low severity, and now lives in `lib/artifact-grouping.ts` after the prior plan landed.
