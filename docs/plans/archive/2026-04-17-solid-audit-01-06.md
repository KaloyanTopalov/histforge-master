# SOLID Audit Refactor — Items #1–#6

## Overview

Act on findings #1–#6 from `docs/refactoring/solid-audit-2026-04-17.md`. The work clusters in three areas: (a) tighten the worker/step composition seam (#1, #3, #4, #6), (b) dedupe a file-tree walker shared by page and API (#5), and (c) extract a repository layer under the dashboard routes so HTTP handlers stop hand-writing SQL (#2, absorbs #9). The payoff is that adding a step, swapping an LLM provider, or changing the `videos` schema each become one-file changes instead of grep-and-edit-many.

The audit explicitly recommends doing #1 before #3 and #6 — they all point at the same step/provider composition friction, and #1 makes the other two smaller. In this plan, Phase 2 creates the LLM registry *infrastructure only* and Phase 3 consumes it from `ctx.chat` so each content step file is touched exactly once. #2 is independent and can run in parallel with the pipeline work.
