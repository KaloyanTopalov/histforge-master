# domain-workflows

Use when modifying: `src/worker/workflows/`, `src/lib/broll/`, `src/lib/tracks-per-album.ts`, the workflow-related parts of `src/worker/pipeline.ts` and `src/worker/runner.ts`, or when adding a new workflow type.

## Rules

- **Workflow = registry entry, not a code fork.** Adding a third workflow means a `WorkflowDefinition` object in `src/worker/workflows/<name>.ts` + a registration line in `index.ts`. NEVER fork `pipeline.ts` or `runner.ts`.
- **Channels carry exactly one workflow.** `channel.workflow` is `'ambient' | 'rap-compilation' | 'ambient-video'` (extend the `WORKFLOWS` const in `src/lib/channels/constants.ts` to add more — `repos/channels.ts` re-exports it). It's NOT NULL with DEFAULT `'ambient'` so existing rows migrate cleanly.
- **Albums snapshot workflow at create time.** `albums.workflow` is denormalized — `albumsRepo.create()` reads `channel.workflow` once and writes it onto the album row. NEVER write to `albums.workflow` from a step or any other place. Historical accuracy depends on this being immutable per album.
- **Pipeline orchestrator stays workflow-agnostic.** It knows: log workflow name; run workflow.preflightChecks before step 01; inject `workflow.branchB` as `deps.branchB` AND optionally `workflow.step01` / `workflow.step05a` when set (so the runner can swap those slots without orchestrator changes). Everything else is workflow-specific code in the workflow's own files.
- **Preflight checks throw `PipelineError` with a code.** Codes used so far: `BROLL_FOLDER_MISSING`, `BROLL_FOLDER_INVALID`, `SUNO_STYLE_PROMPT_REQUIRED`, `SOURCE_JPG_MISSING`, `SCENE_THEMES_INVALID`. Use `RUNTIME_REQUIRED_FIELD_MISSING` style for new ones. Failures fire BEFORE step 01 — the runner's catch transitions album → status='failed'.
- **Branch B is a `PipelineStep` function.** Same shape as ambient's `branchBVideoRender`: `async (album, log) => { await stepN(album, log); ... }`. Sequential within the branch. Failure throws — pipeline orchestrator catches and patches `videoStatus='failed'`.
- **Step 08 is workflow-specific.** Ambient uses `08-loop-to-2h`. Rap SKIPS step 08 entirely. ambient-video replaces it with `08-seedance-clip` (a 10-second Seedance motion clip used as the video bed). When adding a new workflow, default to "skip step 08" unless the workflow genuinely needs a forced fixed-length audio loop — most don't.
- **ambient-video's composed step 01.** `workflow.step01` is `async (album, log) => { await step01AlbumBrief(album, log); await step01bSceneGenerator(album, log); }`. Step 01 produces the album title/genre; step 01b uses OpenRouter (system + user, `temperature: 0.9`, `response_format: json_object`) to produce `{ scene, imagePrompt, seedancePrompt, title }` from a randomly-picked theme in `channel.scene_themes` (null → hardcoded fallback). Writes `albums.scene_image_prompt / scene_seedance_prompt / scene_title` AND `projects/<ch>/<alb>/scene.json` AND a prominent `=`-banner log of the Midjourney prompt.
- **source.jpg is the ambient-video pivot.** Operator generates the Midjourney render by hand from `album.scene_image_prompt` and saves it at `projects/<channel_id>/source.jpg`. The same file is BOTH (1) the input to step 05a-ambient-video-cover (cropAndScaleSquare → cover.png 3000×3000; resizeWithMode → ytImage.png 1920×1080; compressToJpeg if needed for DK), and (2) the `first_frame` AND `last_frame` for Seedance in step 08 so the 10s clip loops seamlessly. Preflight (`requireSourceJpg`) demands the file exists with size > 50 KB BEFORE step 01 to avoid Suno burning 30 credits on a run that can't render its video bed.
- **Seedance is a stateless REST call.** `src/lib/seedance/client.ts` POSTs to OpenRouter `/api/v1/videos` using the same `OPENROUTER_API_KEY` as the LLM — no Chrome, no sidecar, no bridge. The client honors the `apiKey === 'mock'` sentinel (returns a fixture mp4 copy) so step-08 tests can short-circuit. `bytedance/seedance-2.0`, `generate_audio: false`, `aspect_ratio: '16:9'`, `duration: 10`. **The OpenRouter videos endpoint field names are best-effort starting points — verify against the live API on the first end-to-end run; on a 4xx, log the raw error body and adjust.** Error codes: `SEEDANCE_AUTH` (401), `SEEDANCE_RATE_LIMIT` (429/5xx, retriable), `SEEDANCE_NETWORK` (transient), `SEEDANCE_TASK_FAILED` (terminal).
- **ambient-video final mux is `muxVideoBedAndAudio` (`src/lib/render/mux.ts`).** `-stream_loop -1 -i clip.mp4 -i loop.wav -map 0:v:0 -map 1:a:0 -vf <SCALE_PAD> ... -t targetSeconds` produces a 1920×1080 final.mp4 of exact target duration. NVENC/libx264 via `pickEncoder`. The same `-map` mandate as rap branch: without explicit maps ffmpeg may pull the audio from the clip's stream (if any) instead of `loop.wav`.
- **B-roll preflight runs at TWO points** for rap-compilation: (1) channel CRUD validation when POST/PATCHing a rap channel; (2) `workflow.preflightChecks` at orchestrator start. Both call `preflightBrollFolder()` from `src/lib/broll/preflight.ts`. Mid-flight folder mutation is detected by check (2).
- **Track count resolution: `resolveTracksPerAlbum(channel, workflow)`.** Precedence: `settings.tracks_per_album_override` (test escape, 1-30) > `channel.tracksPerAlbum` (per-channel override, > 0) > `workflow.defaultTracksPerAlbum`. Both step 02 and step 06 call this so they agree on N.
- **B-roll selection is deterministic.** `selectBroll({albumId, trackNumber, clips, songDurationSec, strategy})` from `src/lib/broll/select.ts` shuffles via SHA-256-seeded LCG so re-running step 09-rap produces the same final.mp4. Strategies: `random-fill` (per-track seed), `sequential` (path-sorted, ignores seed), `seeded-by-album` (per-album seed — every track gets the same shuffle).
- **B-roll concat is stream-copy at native resolution.** Per-track concat (`song-NN-video.mp4`) and the assemble step (`full-video.mp4`) both use `ffmpeg -f concat -safe 0 -c copy` and stay at the source clip resolution. Mixed codecs across clips would corrupt the demuxer output — preflight detects mixed codecs and surfaces them in `result.codecsDetected` for operator review.
- **Final mux re-encodes both video and audio.** Video is scaled to **1920×1080 with letterbox/pillarbox padding** (`scale=1920:1080:force_original_aspect_ratio=decrease,pad=1920:1080:(ow-iw)/2:(oh-ih)/2:color=black,setsar=1`) so any source aspect fits without distortion. Audio re-encodes PCM `concat.wav` → AAC 192k. Encoder picked via `pickEncoder` (NVENC `h264_nvenc -preset p4 -tune hq -rc vbr -cq 23` when available, else `libx264 -preset medium -crf 20`). Re-encoding cost is bounded to this single final pass; intermediates above stay stream-copy. **`-map 0:v:0 -map 1:a:0` is mandatory**: without it ffmpeg auto-selects the AAC stream from `full-video.mp4` (broll source) over the PCM from `concat.wav` and the song goes missing.
- **Final mux uses `runFfmpegStreaming` for progress reporting.** Mirror the pattern from `src/worker/steps/09-rap-broll-mux.ts`: parse `time=HH:MM:SS.cc` lines, throttle DB writes to every 10%.
- **Per-track files are idempotent.** `song-NN-final.mp4` skipped if duration matches. `final.mp4` skipped if h264 + aac + **dims=1920×1080** + duration ≈ Σtracks ±3s. Re-running step 09-rap on a partial run only re-encodes what's missing; a 360p file from the prior stream-copy era forces a re-render.
- **Workflow defaults map to file basenames** via `defaultPromptBasename(kind, workflow)` in `src/lib/prompts.ts`. Ambient keeps legacy basenames (`cover-prompt.md`, `thumbnail-prompt.md`); rap uses suffix (`cover-image-rap.md`, `thumbnail-rap.md`, etc.). When adding a workflow, decide whether to alias to ambient's defaults or author a new set under `prompts/defaults/<kind>-<workflow>.md`.
- **`PipelineDeps.workflow` is OPTIONAL.** Tests typically inject `branchA`/`branchB` directly without `workflow`, so preflight is skipped. The runner ALWAYS injects it in production. If a future test needs preflight verification, pass `deps.workflow = { name: '...', preflightChecks: [...] }`.

## Anti-patterns

- Writing `if (channel.workflow === 'ambient') { ... } else { ... }` in step code. Steps should be workflow-agnostic. If a step's behavior diverges, it's a different step — make a new step variant. **Single permitted exception:** step 10's `ytTitle` override for ambient-video (uses `album.scene_title` instead of the LLM-generated title). A workflow-supplied `titleResolver` hook is over-engineering for a one-field override.
- Re-encoding concat audio (rap or ambient or ambient-video).
- Reading `albums.workflow` to drive runtime decisions inside a step. Steps that need workflow info should call `getWorkflow(channel.workflow)` via the channel — but this is rare; most steps don't need workflow context.
- Running B-roll preflight from a step (other than step 09-rap, which does it as defense-in-depth). The workflow's `preflightChecks` already runs at orchestrator start.
- Hardcoding `defaultTracksPerAlbum: 30` in step code. Always go through `resolveTracksPerAlbum(channel, workflow)`.
- Writing to `albums.workflow` from anywhere other than `albumsRepo.create()`.
- Reusing `lib/render/mux.ts:muxVideo` for the rap branch or the ambient-video branch. That helper assumes `image + audio` (single static frame); rap needs concat-video + audio; ambient-video needs looped-clip + audio. Use the inline FFmpeg in step 09-rap, or `muxVideoBedAndAudio` for ambient-video.
- Generating ambient-video's `source.jpg` programmatically. The operator runs Midjourney by hand from `album.scene_image_prompt`. Step 05a-ambient-video-cover copies the existing file; step 08 sends it to Seedance as both first and last frame.
- Routing Seedance through a Chrome extension / sidecar. It's stateless REST against OpenRouter — same key as the LLM. No new bridge needed.
- Reading `channel.seedance_motion_prompt` directly from step 08 without checking `album.scene_seedance_prompt` first. Album always wins over channel fallback (album is the per-run generator output; channel is the operator-set default for albums where the LLM hasn't been wired up yet).
- Re-introducing an LLM call to generate `album.scene_*` fields from anywhere other than step 01b. Step 01b owns it; subsequent runs are idempotent (skip when all three scene_* fields are set).
